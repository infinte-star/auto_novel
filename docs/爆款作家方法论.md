# 头部网文爆款作家创作方法论

> 调研对象：番茄（我在精神病院学斩神）、老鹰吃小鸡（不是吧君子也防）、
> 会说话的肘子（第一序列、夜的命名术）、爱潜水的乌贼（诡秘之主）、
> 辰东（遮天、完美世界）、猫腻（庆余年）、天蚕土豆（斗破苍穹）、唐家三少。
>
> 每节末尾标注 **框架覆盖度** 和 **改进方向**，供引擎迭代参考。

---

## 一、选题与定位（创作起点）

### 1.1 定位先于写作

> "定位才是关键。写之前想好这个文是写给谁看的，然后想这些人喜欢看什么。"

核心流程：**读者画像 → 核心卖点 → 书名+简介承诺 → 正文兑现承诺**

- 书名 = 流量入口。免费平台（番茄/七猫）需含爆款关键词（重生/系统/开局/末日/穿越）
- 简介 = 一句话核心卖点 + 爽点承诺，≤ 150 字
- 读者点开时兴趣已经建立；正文的任务是兑现，不是重新说服

### 1.2 题材选择三分法

| 分类 | 定义 | 代入感 | 风险 |
|------|------|--------|------|
| 自创世界观 | 全新异世界/自建体系 | 低（需大量铺垫） | 高：驾驭不住就崩 |
| 主流验证题材 | 都市/玄幻/历史/游戏等 | 中高 | 低：受众稳定 |
| 新兴热点 | 同人/规则怪谈/日常系 | 高（新鲜感） | 中：窗口期短 |

职业作家的共识：新人优先选择已被验证的题材方向，在熟悉框架内做微创新。
乌贼的突破方式：把已有元素跨界组合（克苏鲁+蒸汽朋克+序列体系 = 诡秘之主）。

### 1.3 金手指设计原则

- **有上限**：不能太万能，需使用条件/冷却/成本
- **有成长性**：金手指本身能升级，维持读者期待
- **有谜团**：金手指的来源/本质是一条独立悬念线
- **与人设绑定**：金手指的使用方式反映主角性格
- 老鹰的做法：中医穴位改写等级体系，避免传统体系疲态
- 乌贼的做法：22 条序列途径，每条都是独立的世界观支柱

**框架覆盖度**：★☆☆☆☆ — 选题/定位是 prompt.md 的人工工作，引擎不介入。
**改进方向**：无需引擎改动。可在 `prompt_template.md` 中增加定位检查清单。

## 二、黄金三章（开篇生死线）

### 2.1 底层逻辑

读者有"耐心值"，由书名→简介→第一段逐级消耗。黄金三章的本质是在耐心耗尽前完成"定位→代入→承诺"。番茄平台数据：**前 30 字决定 63% 的留存率**。

### 2.2 三章任务分解

| 章 | 任务 | 必须完成 |
|----|------|----------|
| 第 1 章 | 冲突+主角+代入 | 首句即事件；500 字内主角出场；章末强钩子 |
| 第 2 章 | 人设立体化+首爽 | 动作展示人设；第一个爽点兑现；目标/动机明确 |
| 第 3 章 | 金手指亮相+长线期待 | 绝境触发>平淡获得；世界观揭一层留更多；全书级大钩子 |

### 2.3 开篇反模式（必须避免）

1. 环境描写开场 — 直接劝退
2. 角色名堆砌（首段 5+ 名字）— 读者头晕
3. 非主角开篇 — 无法代入
4. 设定说明书 — 信息过载
5. 无冲突日常 — 无吸引力
6. 内心独白过长 — 没有画面感

### 2.4 职业作家的实际做法

肘子：不教条地套用黄金三章，而是"把书名和简介承诺的剧情老老实实写出来"。
番茄平台作者：开局像过山车，第一段即高密度。不需要刻意制造矛盾冲突，只要核心爽点兑现即可。

**关键认知**：黄金三章不是公式，而是"不让读者在耐心耗尽前离开"的底层原则。具体执行因题材而异。

**框架覆盖度**：★★★★☆ — `opening_rules.md` 覆盖全面；`opening_type` 轮换已编码。
**改进方向**：已足够。knowledge.py 在前 3 章自动注入开篇规则。

## 三、大纲与细纲结构

### 3.1 大纲四层体系

来自多位职业作家的共识结构：

1. **主线故事架构**：从什么局面到什么局面，越细越好
2. **关键转折点标注**：奇遇/战斗/遭遇/转折按时间线排布 → 控制节奏感
3. **人物档案**：性格/外形/特长/口头禅/与主角关系/叙事功能
4. **冲突独立拎出**：弹压设计是小说核心的一半，需要着重设计

### 3.2 两种成功路径

| 路径 | 代表作家 | 做法 | 优势 |
|------|----------|------|------|
| 详尽大纲型 | 乌贼 | 开书前写 3-4 万字大纲；全部设定/伏笔预规划 | 伏笔精密；世界观自洽 |
| 主线锚定型 | 老鹰、肘子 | 只定主线走向，边写边填细节 | 灵活；高产；自然 |

### 3.3 细纲的作用

- 最细的细纲精确到每一章的主要内容
- 核心价值：**人工控制节奏感** — 清楚看到几章出一个高潮
- 有些成功作者完全不写细纲，纯靠经验和直觉

**框架覆盖度**：★★★★★ — 弧级规划（arc_span=10）+ ChapterCard 7 必填字段 + 卷纲
= 自动化的"细纲到每一章"。`volume_plan.md` = 大纲；ChapterCard = 细纲。
**改进方向**：已是框架最强部分。

## 四、爽点三级架构

### 4.1 三级密度标准

| 级别 | 频率 | 效果 | 示例 |
|------|------|------|------|
| 小爽点 | 每章 ≥ 1 | 嘴角微扬 | 一句漂亮话、路人震惊、信息揭示 |
| 中爽点 | 每 3-5 章 | "太爽了" | 完整打脸流程、关系突破、实力跃升 |
| 大爽点 | 每弧/卷高潮 | 想截图分享 | Boss 战逆转、身份曝光、多伏笔回收 |

**数据**：追读率 TOP 10% 作品平均每 1.8 章一次情绪高峰；BOTTOM 10% 每 4.7 章。
**铁律**：**连续 3 章无爽点 = 追读开始掉**。

### 4.2 打脸四部曲（中爽点标准流程）

```
第一拍：铺垫嘲笑（1-2章）→ 读者积累"替主角不值"的情绪
第二拍：压制加码（0.5-1章）→ 对手占上风，读者愤怒值拉满
第三拍：反转碾压（0.5-1章）→ 主角亮底牌，多巴胺释放
第四拍：余震收尾（0.5章）  → 围观者反应 + 后续影响 → 下一轮钩子
```

### 4.3 打脸升级路径（防爽点疲劳）

- 围观人数递增：无人→几人→众人→全场
- 对手层级递增：小喽啰→中层→大佬→终极 Boss
- 打脸方式轮换：实力碾压/智商碾压/身份揭示/资源压制
- 后果递增：面子→利益→势力版图→命运走向

**框架覆盖度**：★★★☆☆ — `payoff_type` 轮换已编码；知识库有完整理论。
但引擎缺少 `payoff_level` (小/中/大) 的显式标注和密度检查。
**改进方向**：ChapterCard 新增 `payoff_level` 字段 + 弧级分布校验。→ **已纳入本次改动**

## 五、落差公式（先压后爽的底层机制）

### 5.1 核心公式

> 落差 = 主角期望 vs 实际结果。爽点的本质是落差后的反弹——落差越大，反弹越爽。

### 5.2 三种落差类型

| 类型 | 铺垫 | 压制 | 反转 |
|------|------|------|------|
| 实力落差 | 以为能赢 | 差点被打死 | 绝境翻盘 |
| 信任落差 | 以为盟友可靠 | 被背叛 | 自立/反利用 |
| 收益落差 | 以为得到宝物 | 是陷阱 | 因祸得福 |

### 5.3 密度标准

- 极端落差（跨卷铺垫）：全书 3-5 次
- 中落差（3-5 章铺垫）：每卷 1-2 次
- 小落差（1-2 章完成）：每 5-8 章一次

### 5.4 职业认知

没有铺垫的碾压是空洞的。肘子在写《第一序列》时会先听悲伤音乐再写压迫段，听激昂音乐再写反转段。**情绪是写出来的，不是标注出来的。**

**框架覆盖度**：★★☆☆☆ — `pressure` 和 `blocked_by` 字段存在但无落差深度检查。
ARC_SYSTEM 提到"先压后爽"但无结构性约束。
**改进方向**：ARC_SYSTEM 新增落差规则。→ **已纳入本次改动**

## 六、节奏控制（憋-炸-余韵）

### 6.1 核心三拍

```
憋（2-3 章）：主角被压制/被误解/被欺负 → 读者积累愤怒/期待
炸（1 章）  ：主角爆发/反杀/身份揭示   → 读者多巴胺释放
余韵（1 章）：围观者反应/对手崩溃       → 余味+下一轮钩子
```

### 6.2 章内节奏四段式

```
开场钩（10-15%）：延续上章悬念/制造新冲突
场景一（30-35%）：主要事件推进
场景二（30-35%）：冲突升级/情感深化
结尾钩（15-20%）：爽点兑现+章末钩子
```

### 6.3 AI 写作的节奏问题

1. **太均匀**：每段相同密度
2. **不会加速**：紧张段仍用长句
3. **不会减速**：温馨段仍然密集
4. **不会留白**：每处都填满

**框架覆盖度**：★★★★☆ — `tension_level` 三档循环 + `validate_card` 防连续同级 +
`check_arc_end_acceleration` 弧尾加速检查 + 知识库有完整节奏模板。
**改进方向**：已足够。knowledge.py 按 tension 动态注入对应模板。

## 七、伏笔体系

### 7.1 密度控制

- 每章至少埋 1 个长期伏笔
- 小伏笔（3-10 章回收）：每章 1-2 个
- 中伏笔（10-50 章回收）：每卷 3-5 个
- 大伏笔（跨卷/全书）：全书 3-5 个

### 7.2 乌贼的做法

> "创作类似推理，先给线索，再推敲解决方案。"

乌贼在开书前写 3-4 万字大纲，把所有核心伏笔的埋设和回收点预先规划好。
22 条序列途径本身就是一个巨大的伏笔体系——每条线的真相在不同时间揭示。

### 7.3 记忆锚点设计

长篇小说读者会忘记 50 章前的细节。锚点 = 让读者记住伏笔的助记符：
- 道具锚点（戒指/日记/匕首）
- 台词锚点（反复出现，每次含义不同）
- 符号锚点（红色/月亮/蝴蝶）
- 场景锚点（回到旧地，物是人非）

### 7.4 回收原则

- 回收时机：大爽点/高潮章/反转点
- 多条伏笔同时回收 = 最强爽点
- 每 50 章回收一个核心伏笔

**框架覆盖度**：★★★★☆ — `thread_actions` 在卡片中标注；`store.py` 追踪线索状态；
`get_overdue_reader_promises` 检测超时伏笔；`quality_advisory` 有 thread_overdue 门。
**改进方向**：线索机制已扎实。主要靠知识库注入提醒具体做法。

## 八、情绪曲线

### 8.1 情绪呼吸法则

情绪像呼吸——吸气（压抑/紧张）后必须呼气（释放/满足）。

**甜虐比黄金比例：7:3**（大部分题材最高完读率）

### 8.2 压抑缓冲规则

- 每 2-3 章虐/压抑后，必须有 ≥ 1 章缓冲
- 缓冲不需要大甜——一个温暖细节、一句安慰、一个小胜利即可
- **"希望感"是追读的根本动力** — 没有希望的虐 = 弃书

### 8.3 肘子的情绪方法

> "写战斗听激昂的歌；写悲痛听悲伤的歌。"
> "他一个人在书房里泪流满面 20 分钟"后才写出陈无敌的死。

**情绪圆融**：对白、动作、心理、环境、人设所有元素为同一情绪服务。
**情绪撕裂**（避免）：情绪将要引爆时被无关事件打断。

**框架覆盖度**：★★★☆☆ — `emotion_target` 字段存在；知识库有甜虐比/曲线模板。
但引擎不检查弧内的情绪波动是否符合"呼吸"模式。
**改进方向**：不做显式检查（难以零 LLM 判断）；靠知识库注入和 ARC_SYSTEM 的
"情绪与节奏编排"section 引导模型。

## 九、章末钩子

### 9.1 六种钩子类型

1. **悬念式**：引入未解答的问题
2. **反转式**：整章暗示 A，最后一行推翻
3. **情绪炸弹式**：矛盾爆发，在最强时切断
4. **信息投放式**：章末重磅信息
5. **威胁/倒计时式**：紧迫的时间限制
6. **温馨/治愈式**：高强度后的温暖收尾

### 9.2 执行规则

- 每章必有钩子
- 类型要轮换（不可连续 3 章同类型）
- 钩子在规划阶段预设（不能写完再补）
- 力度逐章递增

**框架覆盖度**：★★★★★ — `exit_hook` 是 ChapterCard 必填字段；`hook_type` 轮换
已在 `validate_card` 中检查；`refine_card` 也做相邻去重。
**改进方向**：无需改动。

## 十、人物塑造

### 10.1 乌贼的方法

> "以传记、新闻里的细节为原型，以柔和的方式化入，人物形象就能很轻松变得立体。"
> "只要提取科学史上有名的事件，将核心矛盾包装一下，可读性自然上去。"

### 10.2 肘子的方法

> "英雄末路，英雄死了并不可怕，可怕的是这个世界上没有人相信英雄了。"

角色承载作者的价值寄托，人设通过极端情境下的选择展示，而非旁白定义。

### 10.3 反派设计

- 反派作恶按阶梯递增（小恶→中恶→大恶）
- 最好的反派是"在另一个视角下可以是主角"的人
- 乌贼最满意的配角是反派阿蒙——与主角的对决诠释了"人类勇气的赞歌"

**框架覆盖度**：★★★☆☆ — `character_rules.md` 覆盖理论；ChapterCard 有 `who` +
`pov_character`；`entity_state_as_of` 追踪角色状态。
**改进方向**：人物塑造主要靠 prompt.md 的角色设定 + 知识库注入。引擎无需改动。

## 十一、世界观构建

### 11.1 递进揭示原则

**"洋葱式揭露"**：每次只揭示一层，保留更深层做悬念。
- 小世界 → 大世界 → 更大世界
- 每个新地图 = 新的规则/势力/机遇
- 世界观递进和主角成长同步

### 11.2 代入感优先

> "读者喜欢看自己熟悉的背景和世界观——三个字：代入感。"

自创世界观的风险最高；已验证题材的受众最稳定；
新兴热点有窗口期红利但不持久。

**框架覆盖度**：★★☆☆☆ — 世界观构建主要是 prompt.md 的人工工作。
引擎通过 `world_state_changes` 追踪世界变化，但不做递进检查。
**改进方向**：无需引擎改动。靠 volume_plan.md 人工规划世界观递进。

## 十二、信息释放策略

### 12.1 核心原则

- 每次只释放必要信息，保留悬念
- 信息差 = 期待感
- 重要信息不在叙述中直说，要通过场景/对话/动作展示
- 每 2000 字需有 1 次小高潮或信息释放点

### 12.2 双线制约

- 表线（主角成长）：明线推进
- 暗线（世界观升级）：暗中铺垫

**框架覆盖度**：★★☆☆☆ — 知识库有理论；引擎不检查信息密度。
**改进方向**：信息密度难以零 LLM 检测。靠写手 prompt 引导。

## 十三、读者留存与商业化

### 13.1 弃书原因排行

1. 连续多章无爽点/无进展（最致命）
2. AI 感过重
3. 节奏拖沓
4. 人设崩塌
5. 世界观太大驾驭不住

### 13.2 平台差异

| 平台 | 读者耐心 | 核心指标 | 写法要求 |
|------|----------|----------|----------|
| 番茄/七猫 | 极短 | 完读率→广告分成 | 极快节奏，每章都爽 |
| 起点 | 中等 | 追读率→订阅 | 允许慢热但必须有深度 |
| 晋江 | 较长 | 收藏→订阅 | 人设>节奏 |

### 13.3 连载策略

- 日更 ≥ 4000 字是基础门槛
- 头部作家日更 6000-10000 字
- 老鹰部分作品日更可达数万字
- 稳定更新 > 爆发式更新（读者形成习惯）

**框架覆盖度**：★★★☆☆ — `reader_retention.md` 覆盖弃书原因和留存规则；
`style_health` 检测 AI 感；引擎生成速度远超人类。
**改进方向**：连载策略不适用于引擎（引擎全速生成）。留存规则已通过知识库注入。
