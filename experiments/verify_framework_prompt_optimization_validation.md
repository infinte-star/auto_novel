# `verify_framework` 五项 P0 修复与同简报实写验证报告

生成时间：2026-08-04

## 1. 结论

五项 P0 已完成修复，并用与基线字节级一致的 `prompt.md` 重新实写验证。

最终结论：**P0 修复有效，优化后的框架在质量、原始简报遵循和剧情可控性上明显更可靠；按“质量第一”的项目原则，优化后总体更好。**

核心结果：

- 原始简报故事脊柱：基线在当前独立标尺下为 **1/5**，最终认证稿为 **5/5**。
- 最终五章的正文和有效精修稿均通过独立故事脊柱复核；Ch5 的任务等级、收件人、关键因果真相和封闭收束全部落地。
- 完整五章严格运行的 FPY' 从 **3/5（60%）提升到 4/5（80%）**。
- 每章 Prompt 字符约下降 **5%**，估算成本略降。
- LLM 调用数增加 2 次，总 LLM 时间增加约 29%；因此不能宣称“效率全面提升”。
- 精修器把会破坏故事脊柱的 Ch5 改写拒绝掉，并自动保留合格原稿，证明保护链覆盖到了后置精修阶段。

这次结果不是靠词频命中或模型自评分得出。故事脊柱检查独立于卷纲、章节卡和正文生成结果，并额外校验“任务等级”“命名收件人”“关键因果锚点”“终章封闭关系”。

## 3. 五项 P0 修复

### P0-1：契约被 creative boost 污染

**问题**：旧链路先进行 creative boost，再从增强后的文本提取硬契约。模型新增的“记忆邮费”“人格分裂”“竞争配送公司”等候选创意被升级成全书必须遵守的事实。

**原因**：创意扩写与用户意图提取共用同一事实源，后生成且更结构化的信息反而获得更高优先级。

**优化方案**：契约只从原始 `prompt.md` 提取，提取完成后才运行 creative boost；契约条目还需通过原始文本归因清洗。

**预期收益**：阻止模型新增内容污染硬设定，保证用户简报始终是最高事实源。

**潜在风险**：过度保守会漏掉隐含意图。当前用确定性回退补全明确规则，但不把推断结果写入硬契约。

### P0-2：候选创意与硬约束没有权限边界

**问题**：creative boost 的输出可直接进入 bible、卷纲、章节卡和正文，形成一条自洽但偏离用户要求的新故事。

**原因**：Prompt 没有区分“可选灵感”和“不可改写事实”，下游也没有来源级权限控制。

**优化方案**：boost 只保留为候选创意；任何候选内容不得进入 hard contract 或覆盖 story spine。下游 Prompt 明确优先级为：原始简报故事脊柱 > 硬契约 > 已确认连续性 > 当前计划 > 候选创意。

**预期收益**：保留创意增益，同时避免候选设想夺取剧情控制权。

**潜在风险**：候选创意采用率可能下降；这是质量优先下可接受的权衡。

### P0-3：契约提取失败后 fail-open

**问题**：外部调用遇到 403 等故障时，旧框架继续无契约 bootstrap，整本书会在表面成功的情况下失去能力、禁项和剧情约束。

**原因**：错误处理把契约当作可选增强，而不是生成前置条件。

**优化方案**：契约调用失败先按配置重试，再使用只来自原始简报的确定性回退；若原始简报为空或回退仍无法形成有效契约，则终止 bootstrap，禁止空契约继续生成。

**预期收益**：供应商短暂故障不再静默改变小说设计，失败模式从隐性内容损坏变为可见、可恢复的中止。

**潜在风险**：严格失败会降低服务“看起来成功”的比例，但显著降低不可审计坏稿。

### P0-4：明确章节排期可被卷纲和章节卡改写

**问题**：原简报已钉死 Ch1-Ch5 的任务、地点、人物揭示和终局，但旧卷纲可重新安排这些事件。

**原因**：系统只有生成计划，没有独立保存用户指定的不可变章节骨架。

**优化方案**：从原始简报中确定性提取 `story_spine`，保存逐章原文要求、硬锚点、关键因果锚点、任务等级、命名收件人和终章属性。它被注入卷纲、弧规划、章节卡、正文与精修，且不得被任何生成产物改写。

**预期收益**：降低剧情漂移、人物任务错位、终章改写和上下文遗忘，提升长链路首次命中率。

**潜在风险**：语义实现方式很多，逐字匹配容易误杀。当前检查采用保守别名、结构关系和关键因果规则，不要求全部措辞逐字复现。

### P0-5：评审只验证自生成章节卡

**问题**：如果卷纲或章节卡已经漂移，正文忠实执行错误卡片仍能获得高 CCR，形成“系统自证正确”。

**原因**：评审目标与生成目标共享同一份派生计划，缺少对用户原始简报的独立复核。

**优化方案**：正文验收和精修验收均独立对照原始 `story_spine`。一次救援修复后仍不满足故事脊柱则阻断提交；精修稿若退化则不覆盖原稿。

**预期收益**：派生计划无法为自己的漂移背书；后置改写也不能删除关键事实或重新打开已封闭结局。

**潜在风险**：可能增加一次定向救援调用，并使部分精修结果被丢弃；代价可审计且不会破坏合格原稿。

## 4. 额外承重加固

实写验证暴露出若干仅靠普通锚点覆盖率无法解决的问题，已一并修复：

- 命名收件人改为结构关系检查，不能用“死亡概率”或“死神般的提示音”冒充“收件人是死神”。
- 支持合法表达：`收件人【死神】`、`收件人：因果仲裁者（代号“死神”）`。
- 明确拒绝错误表达：`收件人是父亲，死神般的提示音……`。
- 下列关键因果锚点必须全部出现，不能被 60% 普通锚点覆盖率抵消：法医知识、系统版本、系统漏洞、死亡概率、第一代系统快递员。
- 终章增加封闭关系门，拦截新订单、下一任务、待定结算周期、空缺席位等续集钩子。
- 章节卡可用原始简报原文做确定性归位，但不会为已存在的错误收件人关系自动“洗白”。
- fork 对 `prompt.md` 使用字节级复制，避免 CRLF 转换导致 SHA 改变。
- 故事脊柱救援失败后硬终止，禁止带阻断项提交。

## 6. 完整五章效率与 FPY' 对照

为避免 fork 数据失真，本节只比较基线与完整五章运行 `strict_final`。

| 指标 | 基线 `verify_framework` | 完整严格运行 `strict_final` | 变化 |
|---|---:|---:|---:|
| 正文字符 | 17,056 | 16,543 | -3.0% |
| Prompt 总字符 | 461,998 | 438,941 | -5.0% |
| Prompt 字符/章 | 92.4K | 87.8K | -5.0% |
| `llm_calls.jsonl` 记录 | 30 | 32 | +2 |
| 成功调用 | 28 | 32 | +4 |
| 估算总成本 | 约 $0.82 | 约 $0.78 | 约 -4.9% |
| LLM 总时间 | 31.83 分钟 | 41.10 分钟 | +29.1% |
| FPY' | 3/5，60% | 4/5，80% | +20pp |

解释：

- FPY' 使用项目的确定性首轮质量口径，不采用模型自评分；它反映首轮是否需要质量修复，不等同于最终故事脊柱通过率。
- Prompt 和估算成本略降，说明 Prompt 精简仍有收益。
- 调用数和墙钟时间上升，主要来自更严格的契约、卡片修复和保护链；供应商响应延迟也有明显波动。
- `strict_final` 生成后又发现终章留下“下一周期待定”等问题，因此最终内容认证使用后续 `critical_final`；这不改变它作为“完整五章效率样本”的职责。

## 7. 失败实验链与作用

失败样本全部保留，用于说明门禁为何逐步加固：

| 实验 | 暴露的问题 |
|---|---|
| `verify_framework_optimized_p0` | 对所有锚点逐字要求，产生语义实现误杀 |
| `verify_framework_optimized_p0_rerun` | card refine 删除 Ch4、Ch5 的原简报线索 |
| `verify_framework_optimized_p0_final` | Ch5 把收件人改为父亲，旧 matcher 因“死神”词频假通过 |
| `verify_framework_optimized_p0_relation_final` | 关系门首次实验中断/失败 |
| `verify_framework_optimized_p0_strict_final` | 完整五章运行，但终章仍有“下一周期待定” |
| `verify_framework_optimized_p0_closed_final` | 已封闭终章，但遗漏死亡概率与第一代快递员真相 |
| `verify_framework_optimized_p0_critical_final` | 最终认证版本，五章故事脊柱全部通过 |

这条实验链表明，单纯增加关键词并不足够；必须把“事实锚点”“关键因果”和“实体关系”分开校验。

## 9. 剩余风险

- 当前只有一份简报、一次完整严格运行，统计置信度有限；5/5 证明该故障链被修复，不代表所有题材都已稳定。
- 规则仍依赖确定性语言模式。虽然已从词频升级为结构关系，但复杂隐喻、跨段指代和极端表达仍可能误判。
- card repair/refine 调用偏多，质量提高的同时增加了调用数和总耗时。
- 供应商延迟波动较大，单次墙钟时间不能完全归因于 Prompt 架构。
- pairwise judge 仍有位置偏差，且 `n_decisive=0` 的除零问题尚未解决；本报告未使用该盲评支持结论。

## 10. 下一优先级

| 优先级 | 改进 | 预期收益 | 实现成本 |
|---|---|---|---|
| P1 | 减少 card repair 的重复调用，优先使用确定性归位 | 降低调用数和延迟 | 低—中 |
| P1 | 精修只处理存在真实质量债的章节 | 避免无收益改写和故事脊柱回退 | 低 |
| P1 | 用同一简报运行 3 个随机种子 | 验证稳定性和 FPY' 方差 | 中，主要是模型成本 |
| P2 | 修复 pairwise judge 位置偏差和零除 | 恢复可解释盲评 | 中 |
| P2 | 扩充不同题材、不同排期表达的 story spine 回归集 | 降低语言模式过拟合 | 中 |

## 11. 最终判定

五项 P0 已从架构、生成链和验收链三个层面闭环修复：用户原始简报不再被 creative boost 污染，契约失败不再静默放行，明确章节骨架拥有独立且不可变的事实源，正文与精修也不能依靠自生成卡片自证。

最终同简报小说达到故事脊柱 **5/5**，FPY' 在完整严格运行中由 **60% 提升至 80%**，Prompt 字符和估算成本略降。代价是调用数与总耗时上升。

因此，结论是：**质量和可靠性已经实质提升，P0 修复通过验证；效率结构仍需在 P1 阶段继续优化。**
